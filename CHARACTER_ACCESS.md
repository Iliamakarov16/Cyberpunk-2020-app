# Карточки и доступ · 0.14.0

Владелец управляет разрешениями через шестерёнку персонажа → «Кто видит мой лист» либо настройки открытого листа. Разрешения сохраняются отдельно для каждой кампании. У полного листа есть три режима: только владелец и ГМ, вся партия, выбранные игроки. Выбранные аккаунты должны иметь принятый персонаж в этой кампании; резерв сохраняет участие.

Чужой полный лист доступен только для чтения и скачивания. История изменений остаётся у владельца и ГМа. Игроки не получают полномочий редактировать или удалять чужих героев. Право изменить настройки доступа принадлежит владельцу, даже когда ГМ может редактировать сам лист.

Внешняя карточка — отдельная серверная проекция: имя, портрет/цвет, названия, слоты и иконки видимых надетых вещей. Она не содержит характеристик, денег, состояния, описаний предметов, брони, модификаторов, источников, предыстории, личных записей, содержимого рюкзака. Другие принятые участники открывают её в кампании → «Партия» → «Внешность».

Видимость вещи задаётся в её редакторе. По умолчанию скрыты рюкзак, импланты, патроны и нижний слой под курткой; костюм закрывает нижний слой, верх и ноги. Явная отметка «Видно снаружи» позволяет показывать выглядывающую вещь; «Спрятано» скрывает её. Любая видимая вещь всё равно должна быть экипирована и иметь положительное количество. Эти отметки не меняют игровые эффекты и не определяют видимость противникам на боевом поле.

Портрет загружается из PNG/JPEG/WebP до 10 МБ, кадрируется по центру до квадрата 256×256 и сохраняется в листе компактным JPEG. Сервер принимает только ограниченные изображения data URI, без внешних адресов.

Запросы, бывшие участники без принятого героя и предложенные будущие ведущие не получают внешние или полные карточки партии. После удаления связи персонажа с кампанией её разрешения удаляются каскадно. Изменение разрешений меняет версию кампании; изменение внешности меняет подпись синхронизации. Открытый чужой лист перепроверяет разрешение каждые 5 секунд при видимом экране и при возврате в приложение. Устаревший ответ не может открыть лист после более нового отказа.

Разрешение не отзывает копии, которые пользователь уже скачал. Автономное хранилище листов игроков в этой версии не реализовано: для открытия нужен доступный сервер. При переносе кампании через архив разрешения сбрасываются; владельцы выбирают их заново. Полная резервная копия локальной базы сохраняет настройки доступа.

Проверки используют настоящие web API/SQL migrations и Android HTTP/SQLite API. Тесты включают приватную проекцию, выбранные аккаунты, разные кампании, отзыв доступа, историю, редактирование, CAS, атомарные откаты и восстановление владельца без переноса чужого согласия.
