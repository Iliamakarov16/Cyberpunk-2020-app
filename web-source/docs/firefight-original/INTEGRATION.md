# Встраивание боя в приложение кампании

Модуль текущей версии работает локально. Его движок не зависит от интерфейса, но подключение нескольких игроков требует серверной сессии и перевода клиента на серверные команды. Не считать переключатель ГМ/Игрок контролем доступа.

## Готовые точки подключения

```jsx
import BattleApp from '@/components/battle/BattleApp';

<BattleApp
  key={battleId}
  initialScene={battleSnapshot}
  initialRole="gm"
  initialControlledId="character-in-scene"
  allowRoleSwitch={false}
  onStateChange={(nextScene, event) => saveBattle(nextScene, event)}
  onExit={() => openCampaign()}
/>
```

`initialScene` — полный снимок схемы 1, проверяется при создании компонента. Он задаёт начальную сцену один раз: для другой сессии нужно изменить React `key`. При переданном снимке встроенное сохранение в localStorage отключено; сохраняет основное приложение.

`initialRole` принимает `gm` или `player`, `initialControlledId` — ID персонажа в сцене, `allowRoleSwitch=false` скрывает оба демонстрационных переключателя. Если ID отсутствует, выбирается первый участник группы, затем первый участник сцены. Это параметры локального интерфейса, а не серверные права.

`onStateChange(nextScene, event)` вызывается после команды, отмены, импорта и сброса. `event=null` означает замену/восстановление снимка. Полный снимок передаётся только доверенному коду приложения, а не другим игрокам. `onExit` добавляет кнопку возврата в кампанию. Также публикуется браузерное событие `cyberpunk-battle:change` с `{ ruleset, version, state }`; его `state` — обзор текущей роли, не полный снимок игрока.

### Файлы для переноса

- `components/battle/BattleApp.jsx`, `CombatFeedback.jsx`, `NetControls.jsx`
- `lib/battle/engine.mjs`, `scene.mjs`, `renderer.mjs`, `net.mjs`, `audio.mjs`
- `components/ui/dialog.tsx`, `select.tsx`, `switch.tsx`, `button.tsx`, `lib/utils.ts`
- `app/globals.css` или выделенный CSS для экрана боя
- `public/art/combat-atlas.png`, `concrete-floor.png`, `grid-aligned-props.png`
- Тесты из `tests/` и эта документация

Нужны React/React DOM 19, lucide-react, radix-ui, class-variance-authority, clsx, tailwind-merge, Tailwind CSS 4 и tw-animate-css. Псевдоним `@/` должен указывать в корень проекта. Эталонные версии сохранены в `package.json` и lockfile основного исходного проекта.

CSS прототипа намеренно занимает весь экран и задаёт `html/body overflow:hidden`. В приложении кампании нужно ограничить оформление маршрутом боя, чтобы обычные вертикальные страницы сохраняли прокрутку. Экран использует `100dvh` и safe-area inset. Orientation lock вызывается после явного перехода в полный экран; при отсутствии поддержки остаётся просьба повернуть телефон. Для WebView/нативной оболочки горизонтальную ориентацию задаёт оболочка на время маршрута боя.

## Контракт движка

```js
import {
  applyCommand, previewCommand, viewFor, validateSnapshot
} from './lib/battle/engine.mjs';

const context = { role: 'gm', controlledId: 'ray' };
const command = {
  id: crypto.randomUUID(),
  expectedVersion: snapshot.version,
  type: 'shoot', actorId: 'ray', targetId: 'guard-1',
  location: 'torso'
};
const preview = previewCommand(snapshot, command, context);
const { state, event, duplicate } = applyCommand(snapshot, command, context);
const playerView = viewFor(state, 'player', 'ray');
```

`applyCommand` не изменяет входной снимок. Повтор того же `id` возвращает `duplicate=true` и не расходует ресурсы; новая команда с устаревшей `expectedVersion` отклоняется. В сцене хранится последние 1000 применённых ID. Для серверных гарантий дедупликации хранить ID транзакций в БД без ограничения этим локальным окном. Случайность передаётся четвёртым аргументом `rng`, что позволяет воспроизводить проверки в тестах.

Действия персонажа: `move` (x/y), `shoot` (targetId/location), `reload`, `interact` (x/y), `connect` (deviceId), `disconnect`, `scan`, `control` (deviceId/operation), `end`. Для `control` допустимые операции возвращает `deviceActions`: door=open/close, camera=observe, speaker=on/off. Инструменты ГМа: `place`, `start`, `pause`, `resume`, `finish`, `hide`, `paint`, `door`, `add`. Поля проверяются движком; расстановка и редактирование карты доступны до/после боя.

Игроковый обзор содержит только доступных персонажей и собственные подробные характеристики. Состояния active/stunned/dead видимых участников открыты; чужие броня, ранения в числах, характеристики и дека закрыты. Для собственного выстрела виден бросок, для чужого — публичный итог. Для собственного Control видны программа/STR/d10, для чужого — только успех и выполненная операция. Обзор клонирует устройства и не меняет исходный снимок. `order` содержит только видимых участников; `currentActorId=null`, `index=-1`, `gmTurn=true` обозначают текущий ход скрытого НПС без раскрытия его имени и числа других скрытых участников. Полный снимок импортируется через `validateSnapshot`; обзор игрока не является импортируемой сценой.

## Следующий этап: общая сессия

1. ГМ нажимает «Объявить бой» в кампании. Сервер создаёт `battleId`, карту и снимки участников из актуальных карточек; открывается подготовка.
2. ГМ расставляет фигуры, задаёт видимость и выбирает участников. Приглашения появляются внутри уже существующей сессии кампании, с привязкой account → characterId → actorId. Прототип приглашения не отправляет.
3. После старта сервер принимает команды, определяет `role/controlledId` по сессии, блокирует запись сцены в транзакции и вызывает `applyCommand`. Клиент не передаёт себе права ГМа и не бросает результат для сохранения.
4. Сервер сохраняет новую версию и журнал, затем рассылает каждому участнику `viewFor` для его роли. Не отдавать игроку полный `state`, даже если часть данных скрыта CSS.
5. Интерфейс нужно подключить к этим обзорам и отправке команд через транспорт. Текущий `BattleApp` выполняет команды локально над полным снимком; простого добавления WebSocket к `onStateChange` недостаточно. `previewCommand` также возвращает полные объекты персонажей — серверный ответ предпросмотра должен отбирать только разрешённые поля.
6. Переподключившийся клиент получает последнюю разрешённую версию. Повторная доставка команды использует прежний ID. Серверный undo создаёт **новую** версию; локальный undo прототипа восстанавливает предыдущий номер и не подходит для общей сессии.
7. «Завершить бой» сохраняет изменения ранений/брони/патронов в карточки кампании ровно один раз и переводит сессию в `ended`. Экран возвращается в обычную вертикальную часть приложения.

Карта и набор участников не должны жить отдельно от кампании после подключения: персонаж сохраняет `characterId`, а сервер фиксирует исходный revision карточки, чтобы последствия боя не перезаписали параллельное редактирование инвентаря.

## Проверка после переноса

Запустить тесты движка/камеры, проверить фоновые пути изображений, открыть сцену на телефоне в обеих ориентациях. Для сервера дополнительно проверить владение персонажем, скрытых НПС в сетевых ответах, повтор команды, устаревшую версию, отключение/переподключение и однократную запись последствий боя.

## Дополнительные поля снимка

Схема остаётся 1 для совместимости. `devices` опционален при импорте старой сцены и нормализуется в пустой массив. Типы: `port`, `door`, `camera`, `speaker`; общие поля: id/name/networkId/x/y. Дверь привязана к клетке door, камера имеет range/active, громкая связь — active.

У нетраннера: `stats.interface` и `net={deck:true,programIds,linkedPortId,knownDeviceIds,controlUsed}`. ID программ текущей сборки: genie/crystalBall/soundmachine. В начале нового раунда `controlUsed=false`; отключение кабеля не восстанавливает попытку в том же раунде. Старым персонажам дека автоматически не добавляется. `demoRevision=2` только отмечает новую демонстрацию; старое сохранение не заменяется без подтверждённого сброса.

Контроль устройств меняет общий снимок (дверь, тревога, обнаруженные камерой фигуры). Условия кабеля/локальной сети/одной попытки и камеры перечислены в RULES.md как соглашения прототипа. Если приложение кампании использует беспроводную деку либо MicroNET, добавлять их отдельными правилами и командами.

Эффекты Canvas и необязательный WebAudio не изменяют RNG движка. Звук включается пользователем, хранится отдельно от снимка, запускается после подтверждения выстрела. При reduced motion остаётся статическое обозначение итога. Перед перенесением следует проверить звук, диалог Сети и карточку результата в настоящем браузере телефона.
